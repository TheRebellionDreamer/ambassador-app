## Что уже решено (не пересматриваем без согласования с BE)

- **Стек FE:** Vite + React 19 + TypeScript, Mantine 9 (UI, даты, уведомления), react-router, react-hook-form + zod,
  Dexie (IndexedDB) + dexie-react-hooks, vite-plugin-pwa, Яндекс Карты JS API 3.
- **Offline-first:** локальная БД Dexie — источник правды для UI.
  - Любая правка пишется в Dexie и одновременно в таблицу `outbox`.
  - Sync-воркер отправляет outbox (`POST /sync/push`), затем забирает изменения (`GET /sync/pull?since=cursor`) и применяет их в Dexie.
  - UI читает данные только из Dexie через `useLiveQuery`, сетевой запрос в компонентах не делаем.
- **UUID генерирует клиент** (`crypto.randomUUID()`) для всех сущностей.
- **Удаление мягкое:** запись с `deletedAt`, пришедшая через pull, удаляется локально.
- **Склад — журнал движений.** Остаток = сумма `delta`. При создании дегустации FE сам создаёт движение `-1`,
  при удалении — `+1` (подробно в `PLAN.md`, раздел 5.4).
- **Контракт** (zod-схемы сущностей, формат push/pull) лежит в `packages/shared` (`@ambassador/shared`).
  Типы и enum-ы берём оттуда, свои копии не заводим. Менять схемы можно только через изменения в `packages/shared`,
  которые я согласую с BE.
- **Auth:** access JWT держим в памяти, refresh — httpOnly cookie (`credentials: 'include'`). Открытой регистрации нет.

## Моя зона ответственности

- Экраны:
  - карта;
  - список заведений;
  - карточка заведения;
  - форма визита с дегустациями;
  - склад;
  - маршруты;
  - план;
  - вход;
  - профиль.
- Dexie-схема, outbox, sync-воркер, индикатор несинхронизированных изменений.
- PWA: установка на телефон, оффлайн-оболочка.
- Яндекс Карты:
  - ключ в `VITE_YMAPS_API_KEY`;
  - долгий тап по карте создаёт заведение;
  - обратный геокодинг адреса;
  - геолокация.

  Без сети тайлы карты не грузятся. В этом случае показываем список заведений.

- Интерфейс в первую очередь для телефона (одна рука, на ходу), всё на русском.

## Где что лежит

```
apps/web/src/
  app/       провайдеры (Mantine, даты ru), роутер, тема
  pages/     экраны
  features/  сценарии (форма визита, отметка точки маршрута, приход на склад…)
  entities/  UI и хуки сущностей (place, visit, flavor, stockMovement…)
  shared/    api (HTTP-клиент), db (Dexie), sync (outbox + pull), ui, lib
```

Команды (из корня): `pnpm install`, `pnpm dev:web` (FE), `pnpm dev:api` (BE, нужен Postgres), `pnpm build`, `pnpm typecheck`.
Если меняешь `packages/shared`, пересобери его: `pnpm --filter @ambassador/shared build` или `pnpm dev` (watch).
